这份文档是播放链路的**设计评审清单**：先把已经做完的固化成基线，再列出待优化项，每项给出问题、方案、影响面、风险与验收方式，方便逐条拍板。

## 0. 结论摘要

- **基线已经补齐**：播放控制（进度拖拽/键盘/缓冲/倍速/静音/断点续播/失败重试）、歌词舞台（偏好持久化、±5s 时间校准、字号、失败重试）、桌面歌词窗（与主窗口共用偏好）、队列（搜索/打乱/去重/总时长/拖拽/键盘）、空间音效（挂起自动恢复、开关记忆）、离线副本（删除时不打断播放）、播放器形态（标准/迷你/沉浸）都已落地并有测试覆盖。
- **下一步建议优先级**：① 音效预设（均衡器）→ ② 迷你形态贴边与自动隐藏 → ③ 全屏「正在播放」页。三者都是纯前端、可增量交付，且不依赖后端改动。
- **需要后端配合的**（埋点/统计/歌词纠错/响度归一化）单独放在 P2，等前端形态稳定后再动。

## 1. 设计原则（后续所有改动都要过的基准）

1. **播放永不中断**：任何偏好、形态、缓存操作都不能打断正在播放的音轨。已经在「删除正在播放的离线副本 → 切回在线音源并续播」上落地，后续改动沿用同一处理：先换源、再恢复进度、最后给提示。
2. **偏好可迁移**：用户可调项一律进 store 并持久化（`mh_player`），跨会话保留。
3. **能力不可用 ≠ 清除偏好**：音源不支持或浏览器拒绝时，只关掉本次会话并说明原因，偏好保留（空间音效已按此实现），换一首可用的歌还会自动套用。
4. **降级要有反馈**：不支持就明确告知（"该音源不支持空间处理，当前保持原声播放"），绝不静默失败或静音。
5. **键盘与无障碍是默认要求**：进度条、队列行、歌词行都有键盘路径与 aria 语义（队列已改为 listbox/option）。
6. **桌面端不越权**：桌面集成默认关闭；本机 API 只监听回环 + 令牌；歌词窗只接收白名单字段（主进程 `sanitize`），不接收队列、凭据、音频地址。

## 2. 待优化项

### P0-1 音效预设（均衡器）

- **问题**：现在只有「原声 / 3D 空间」两档，用户无法按曲风或耳机调音。
- **方案**：在 `utils/spatialAudio.js` 的图里，于 `masterGain` 前串一组 `BiquadFilter`（建议 6 段：60/150/400/1k/3k/12k，peaking + 首尾 lowshelf/highshelf），预设：原声、流行、摇滚、人声、电子、耳机增强，另留自定义（滑杆持久化）。与 3D 空间叠加：空间处理走 panner 支路，均衡挂在总线上，两者独立开关。
- **影响面**：`utils/spatialAudio.js`（新增 `setEqualizer(bands)` / `EQ_PRESETS`）、`store/player.js`（新增 `equalizer` 偏好并持久化）、`PlayerBar.vue`（预设下拉 + 自定义面板）、README。
- **风险**：**跨域音源不进 Web Audio**（现有安全约束：自定义源/外链媒体不接入，避免 CORS 导致无声），因此均衡只对同源与本地音频生效——UI 必须明示"当前音源不支持音效处理"，否则会被当成 bug。另外滤波器串联会引入轻微延迟与削波，需要在总线末端加 `DynamicsCompressor` 或把 `masterGain` 降到 0.9 留出余量。
- **验收**：预设切换即时生效且无爆音（增益用 `setTargetAtTime` 平滑）；切歌、换源、重载后预设保持一致；跨域音源下按钮置灰并给出提示；单测覆盖预设归一化、非法频段回落、与 `setEnabled`/`setVolume` 的组合。

### P0-2 迷你形态的贴边与自动隐藏

- **问题**：迷你条目前仍固定吸底、占一条完整的横向空间，在小屏或长期挂机时仍然挡内容。
- **方案**：迷你形态支持拖动到屏幕左/右/底边（拖拽把手 + 位置持久化），鼠标离开 3 秒后降到 25% 透明度，移入恢复；双击回到标准形态。用 `transform` 定位，不动布局流。
- **影响面**：`PlayerBar.vue` 增加拖拽逻辑与位置偏好；`store/player.js` 增加 `playerBarDock`（`bottom` / `left` / `right`）持久化；`global.css` 补充贴边样式与 `--player-h` 的对应值。
- **风险**：拖拽与进度条拖拽的手势冲突（把手限定在条左侧空白区）；贴边后 `--player-h` 不再等于内容避让高度，需要按 dock 位置分别给 `padding-bottom` / `padding-left`。
- **验收**：三种停靠位置刷新后保持；拖到边界内不越界；自动隐藏期间键盘焦点进入迷你条立刻恢复不透明；窄屏（≤680px）禁用左右贴边，只保留吸底。

### P0-3 全屏「正在播放」页（Now Playing）

- **问题**：沉浸形态现在复用歌词面板的 3D 舞台，视觉很重，但不适合"想看大封面 + 队列"的场景。
- **方案**：新增第四种形态或沉浸形态内的两个 Tab：舞台（现有 3D 歌词）/ 详情（大封面 + 曲目信息 + 当前队列 + 相似推荐）。复用 `HoloProjector` 与队列列表组件，路由用 `?now-playing=1` 而不是新增路由，避免破坏现有导航分组。
- **影响面**：新增 `components/NowPlayingStage.vue`；`PlayerBar.vue` 形态切换扩成 4 态或沉浸内 Tab；`LyricPanel.vue` 保持独立。
- **风险**：与现有"歌词面板"概念重叠，容易做成两套歌词 UI。约束：歌词渲染只有 `LyricPanel` 一处，Now Playing 页只复用它的**行组件**，不复制逻辑。
- **验收**：沉浸形态下两个视图切换不重启播放、不丢进度；Esc 逐级退出（Tab → 沉浸 → 标准）；键盘可完整操作。

### P1-4 播放模式扩展

- **问题**：现有 顺序/列表循环/单曲循环/随机 中，"随机"是真随机，容易连续抽到同一首或连续抽到同类。
- **方案**：新增 **不重复随机**（shuffle bag：一轮内不重复，抽完重洗）与 **心动模式**（收藏 + 近期常听加权，权重存本地）。`store/player.js` 里 `next()` 的分发逻辑抽成策略函数，便于单测。
- **风险**：低。需要保证"下一首优先（playNext）"与"播完当前停止"两个既有语义不被打乱，睡眠定时与单曲循环的组合行为要有明确定义。
- **验收**：不重复随机在 N 首队列内一轮不重复；心动模式在空收藏时退化为不重复随机；既有 `mode` 的持久化键不变，老数据平滑升级。

### P1-5 队列批量操作

- **问题**：队列只能逐首上移/下移/删除，整理 50 首以上的队列很痛苦。
- **方案**：队列抽屉支持多选（勾选框 + Shift 连选），批量"移到队首 / 移到下一首之后 / 删除 / 保存为歌单"。保存为歌单直接复用现有账号歌单接口。
- **风险**：与拖拽排序共存时，多选状态需要明确规则（拖拽只对单选项生效）。
- **验收**：批量操作后 `currentIndex` 正确跟随当前曲目；清空选择后不影响播放。

### P1-6 交叉淡入淡出（Crossfade）

- **问题**：切歌瞬间有轻微爆音与静音间隙。
- **方案**：切歌时保留旧音轨 30–80ms 淡出、新音轨同步淡入，用 `GainNode` 或媒体元素 `volume` 定时曲线实现。
- **风险**：**空间音效已占用第二个媒体元素**，交叉淡入需要第三个媒体元素或仅在"原声模式"下启用；跨域音源不进 Web Audio 时只能用 `volume` 曲线（精度差、可能触发自动播放限制）。建议先只在原声模式 + 同源音源下启用，其余保持现状。
- **验收**：开关默认关闭；开启后切歌无爆音；睡眠定时"播完当前停止"与交叉淡入不冲突。

### P2-7 断点续播扩展到队列级

- 现在只续单曲进度（`resumeSongId` / `resumeTime`）。建议扩展到"上次整个队列 + 播放位置 + 模式 + 倍速"的会话快照，冷启动后询问"继续上次的收听？"。需要给快照加版本号与失效时间，避免长期陈旧。

### P2-8 播放统计与收听报告

- 依赖后端埋点（现在只有播放历史）。建议先定义事件（播放/完整播放/跳过/收藏来源），前端只上报事件，不做本地统计口径。

### P2-9 歌词时间轴纠错与提交

- 用户在播放器里校准的偏移（±5s）目前只存在本地。建议允许"提交修正"，进入管理员审核闭环（与短评审核同一套）。需要后端字段 `lyricOffsetMs` 与审核队列。

### P2-10 响度归一化

- 不同来源的音频响度差异明显。前端只能做粗略测量（Web Audio `AnalyserNode` 采样），准确方案要后端预扫描写入 `loudness` 字段。建议等 P2-8 的埋点体系稳定后再做。

## 3. 能力降级矩阵（不可用时怎么表现）

| 能力 | 不可用条件 | 现在的行为 | 建议 |
| --- | --- | --- | --- |
| 3D 空间音效 | 跨域/自定义源音源 | 提示"该音源不支持空间处理"，保持原声 | 保持；按钮改为置灰 + tooltip 说明原因 |
| 3D 空间音效 | 浏览器不支持 Web Audio | 提示"空间音效无法启动"，偏好保留 | 保持 |
| AudioContext 被挂起 | 后台标签页/休眠 | 播放与页面回到前台时 resume | 保持；补一条"若仍无声，点重试"的兜底入口 |
| 断点续播 | 本地/自定义源曲目 | 不记录（blob/签名地址不入库） | 保持 |
| 离线副本 | 非本站演示音频 | 拒绝保存并提示"只能保存本站演示音频" | 保持 |
| 桌面歌词窗 | 未开启桌面集成 | 不推送状态 | 保持 |
| 均衡器（待做） | 跨域/自定义源音源 | — | 置灰 + 提示，不静默失效 |

## 4. 建议实施顺序

1. **P0-1 均衡器**（用户感知最强，且能复用已有 Web Audio 图；
   先把 `setEqualizer` 与预设做纯函数化，便于单测）
2. **P0-2 迷你贴边**（形态开关已经落地，贴边是它的自然延伸）
3. **P0-3 Now Playing 页**（若更看重"看大封面"的场景，可与 2 互换顺序）
4. **P1-4 / P1-5**（纯逻辑改动，风险最低，适合穿插）
5. **P1-6 交叉淡入**（涉及第三个媒体元素，放在形态稳定之后）
6. **P2 系列**（等后端配合）

每一轮交付都沿用现在的验收口径：`npm test`（web jsdom + store 单测）、`music-holo-desktop` 桌面前单测、Playwright 关键路径、Docker Compose 全栈 smoke，四条全绿才合并。
