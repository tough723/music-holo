# 音乐平台能力盘点与本项目补齐计划

> 目标是提炼主流产品的通用交互能力，形成原创的 Music Holo 体验；不复制竞品 Logo、专有文案、版权音频或商业素材。

## 市场能力观察

| 方向 | 成熟产品常见做法 | 对本项目的启发 |
| --- | --- | --- |
| 个性化发现 | Spotify 提供 Spotify Mixes、Discover Weekly、Release Radar、Daylist 等面向不同时间与偏好的歌单；Apple Music 根据聆听历史推荐艺人与专辑。 | 从收藏、最近播放、曲风分类、歌手偏好生成可解释的“为你推荐”，冷启动回落到热歌榜。 |
| 搜索 | YouTube Music 支持按歌词找歌；成熟搜索通常横跨歌曲、艺人、歌单等内容类型。 | 做统一搜索入口，歌词、歌名、专辑、歌手、歌单均可成为入口。 |
| 连续收听 | 个性化混音、自动续播、最近播放与年度回顾降低“下一首听什么”的成本。 | 最近播放已按用户保存，支持分页、单条删除与清空；本轮在首页增加「继续收听」快捷入口，点选最近曲目即可恢复播放，不额外复制一份历史数据。 |
| 社交与 UGC | Spotify 有好友分享、协作歌单与 Jam；网易云强调 UGC 歌单、乐评、一起听及社区。 | 已有用户歌单、公开分享链接，以及歌曲/歌单短评 MVP（分页、发布、点赞、举报、管理员审核）；关注歌手、协同编辑与一起听仍属后续独立阶段。 |
| 歌词与演出 | Apple Music 强调实时歌词、翻译/发音；YouTube Music 用 Samples、艺人电台和视频帮助发现歌曲。 | 现有 LRC 同步播放已具基础；后续可加翻译歌词、多语言索引、相似歌曲电台。 |

## 与当前项目对照

### 已有

- 歌曲/歌手/歌单/分类浏览，关键字筛选与分页。
- 全息主题、收藏、个人播放队列、LRC 同步歌词、歌单 CRUD。
- 管理后台、文件上传下载、歌手 CSV 导入导出。
- 播放器适配窄屏，并支持空格播放/暂停、方向键跳转、Shift + 方向键切歌、L 打开歌词、Q 打开队列。

### 本轮补齐

1. **全站 3D 视觉贯穿**：统一空间环境层（透视网格、轨道光环、体积光与粒子），将景深玻璃、轻量卡片倾斜、播放器投影与动态主题覆盖到登录、内容、管理和播放流程，并尊重系统减少动态效果设置。
2. **统一搜索**：跨歌曲（标题/专辑/歌词/歌手）、歌手、公开歌单检索；搜索入口支持 `Ctrl/⌘ + K`。
3. **最近播放**：后端按用户保存歌曲与最后播放时间/次数，可分页、移除单项、清空；播放量接口对匿名访问开放，但只有登录用户写个人历史。
4. **个性化推荐**：按用户近期播放与收藏的歌手/分类做透明的内容匹配；新用户与匿名用户回落到热歌榜。这是可解释的冷启动基线，不宣称为机器学习算法。
5. **排行榜**：综合榜与分类榜，基于已有播放量排序。
6. **隐私补强**：私密歌单详情与曲目必须由创建者或管理员访问；匿名用户“只看我的”返回空结果。
7. **每日推荐入口**：新增独立的每日推荐页，复用用户近期收听/收藏画像，支持按曲风筛选、批量播放和加入队列；匿名访问回落到热歌推荐。
8. **睡眠定时**：播放器提供 15/30/45/60 分钟后暂停，或播完当前曲目后停止；切歌会取消“播完当前曲目”模式，跨路由保留。倒计时使用本机时钟，不是操作系统闹钟；刷新会重置，浏览器/系统挂起时可能延迟触发。
9. **公开歌单一键分享**：公开歌单详情增加原生系统分享与复制链接回退；私密歌单不显示分享入口，URL 由当前站点路由生成，不依赖第三方服务。
10. **本地音频与浮动播放器（本轮）**：队列支持多选本地音频文件，临时 Blob URL 只在浏览器内播放、不上传服务端，也不写入远程播放历史；固定播放器和歌词层 Teleport 到 body，脱离 3D / overflow 祖先布局，滚动页面时保持悬浮。刷新需重新导入；浏览器编解码支持因格式/平台而异。
11. **歌曲 / 公开歌单短评 MVP（本轮）**：游客可分页读取公开短评，登录用户可发布（最多 500 字、每分钟 3 条）、点赞、举报，作者只能删除自己的内容；私密歌单短评沿用所有者/管理员访问权限。管理员可驳回举报、隐藏/恢复短评；隐藏时同一短评的待处理举报一并结案，审核说明仅作者与管理员可见。Mock、API 权限测试与 Playwright 端到端旅程同步覆盖；UGC 即时公开，真实试运行前须明确举报队列责任人。
12. **首页继续收听（本轮）**：已登录用户首页读取自己的最近播放记录，展示少量一键续播卡片，并可跳转完整历史页；游客不请求私人历史。首页各个 discovery API 改为独立容错，单个推荐模块暂时失败不会清空其他已加载内容，显示明确错误和重试入口。复用现有历史接口，不增加新表或埋点。
13. **每日推荐失败态修复（本轮）**：推荐接口暂时失败时，不再把“无法连接”伪装成“当前没有推荐”，也不清空之前已加载的歌曲；页面显示可重试提示。分类筛选或收藏状态接口单独失败时，仍保留可用的推荐列表。未增加新接口、数据库或分析埋点。
14. **HRTF 虚拟空间音效（本轮）**：播放器新增耳机空间音效开关，对本地 Blob / 同源立体声音源做左右虚拟声源 HRTF 混合，保留原声路径并能随时切回；跨域音源继续走原生播放器、不接入 Web Audio。它是可选的虚拟声场处理，不是多声道母带或头部追踪，不宣称为真 Dolby Atmos。未增加服务端或存储依赖。
15. **系统媒体控件接入（本轮）**：通过浏览器 Media Session API 同步曲名、歌手、封面和进度，并响应系统/耳机的播放、暂停、上一首、下一首及 seek 操作。仅在浏览器支持时启用；不增加第三方脚本、音源接口或后端依赖。

## 下一步建议（按 ROI 排序，有明确收口条件）

> ROI 按“可验证的用户/交付收益 ÷ 实施与维护投入”做相对排序，不作未经测量的增长承诺。投入按熟悉 Vue + Spring 的一名全栈工程师估算；本项目未记录实际工时，因此标为估算，不冒充实际 ROI。当前没有真实用户行为基线，不填写虚构转化率。
>
> **本轮 web 优化收益**：延续主流音乐产品的「最近播放 / 每日推荐」习惯：首页复用个人历史 API 一键续播；每日推荐区分接口故障与真实空结果，并允许重试。播放器增加可随时还原的 HRTF 虚拟空间音效，以及浏览器支持时的系统媒体控件/耳机按键操作。可验证收益是少一步回到历史页、推荐故障不再误报为空、原声/虚拟声场可切换，以及系统控制能可靠控制网页播放器；没有真实用户数据，不宣称留存或播放量提升。页面旅程覆盖首页续播、每日推荐、空间音效和系统媒体控制；本轮不加数据库或埋点。

| 排名 | 下一步建议 | 估算投入 | 完成后的可验证收益 | 验收条件 / 指标 | ROI 判断 |
| --- | --- | --- | --- | --- | --- |
| 1 | **歌曲短评小范围试运行与审核值守**：功能和队列已交付；下一步重点是确认确实有人用、并有人负责内容安全，不先堆新社交功能。 | 上线前指定责任人与流程约 0.5–1 人日；如需聚合运营报表约 1–2 人日；持续审核工时单独核算。 | 判断短评是否有实际使用、投诉量是否可承接、处理是否及时，据此决定继续开放、调整或关闭。 | 先确定试运行窗口（建议 2 周）和处理时限；每周记录发评人数/条数、举报数、待处理数、隐藏/驳回数及处理时长中位数/P90。先观察基线，不预设增长率；没人值守就不要面向真实用户开放发布。 | **最高（有条件）**：代码已完成，当前主要成本是运营；先验证风险和需求比再继续开发更划算。 |
| 2 | **推荐反馈最小测量**：确认首页/每日推荐的曝光、播放、跳过与收藏是否能形成可用判断，再考虑改推荐规则。 | 约 2–4 人日开发与隐私评审，之后至少一个明确观察周期；不含运营分析。 | 能看出哪些推荐被播放或收藏、哪些被快速跳过，避免凭主观反复调整首页排序。 | 明确事件定义、用户告知与删除策略；验证曝光到播放/收藏事件完整性；样本少只报数量，不推断效果。只有出现稳定使用量且数据足以支撑比较，再排算法/排序改动。 | **中高（需先有流量）**：可改善发现效率，但当前没有真实用户基线，立即上线复杂埋点/算法 ROI 不确定。 |
| 3 | **关注歌手 + 新歌动态（条件项）**：只有在项目能稳定提供已授权的新歌/艺人更新时才做；不具备更新来源就不做“空关注”。 | 数据源已有时约 3–5 人日；内容维护与通知后续持续投入另计。 | 用户可追踪感兴趣的歌手，并从更新入口发现新作品；可用关注后新歌打开/播放计数验证入口是否被使用。 | 先确认授权目录和更新频率；若至少有一批可持续更新的艺人，再做关注、取消关注、新歌列表；若连续观察周期无更新内容，停止扩展。 | **中或偏低**：标准音乐社区能力，但强依赖内容供给；没有曲库更新不值得先建关系层。 |
| 4 | **协作歌单 / 一起听** | 约 1–3 周起，另有实时服务、权限冲突与长期运维成本。 | 支持共同编辑或同步聆听，增强社交场景；但不能只靠 UI 证明价值。 | 先通过用户访谈确认真实共同收听需求；独立 RFC 处理邀请权限、退出、断线、冲突、举报与隐私。任一关键规则未定，不进入实现。 | **目前最低**：投入明显高于单人收听与短评；等待短评/分享试运行的真实行为证据。 |

### 建议的版本收口线

- **本轮功能范围**：参考 LX Music 的通用播放器习惯，在不复制其 Electron 项目和不接入第三方源脚本的前提下，补齐首页最近播放一键续听、每日推荐故障态与重试、HRTF 虚拟空间音效、浏览器系统媒体控制；短评 MVP 及审核闭环沿用既有验收。继续保持“一起听”不在本轮范围。
- **验证状态如实记录**：本地 Mock API 测试（27 项）、空间音效单测（2 项）与系统媒体控件单测（4 项）通过，前端生产构建通过。当前提交的 [CI run 37828380127](https://github.com/tough723/music-holo/actions/runs/37828380127) 全绿：前端测试/构建/审计、后端 Maven `verify`、9 条生产浏览器旅程和 Docker Compose smoke。系统媒体控件旅程验证元数据同步、系统动作注册以及播放/暂停回调。本工作沙箱未安装 Chromium、Java/Maven 或 Docker，因此浏览器/后端/容器检查在 CI 执行；不得将其表述为本地验证。
- **短评开放边界**：短评发布后立即公开，不是预审制。真实用户试运行前必须指定处理举报的责任人、值守安排和处理时限；若没人负责审核，不对真实用户开放发布入口。每周观测实际发评、举报、隐藏/驳回与处理时长，再决定是否继续投入。
- **下一小版本边界**：9 条 Playwright 旅程（含首页续播、每日推荐筛选/播放、空间音效开关、系统媒体控件）已在 CI 验收通过，作为当前基线；只在出现可复现问题或行为变更时扩展，不做无证据的视觉微调、不加“一起听”。版权曲库、MV、无损音源需要授权或独立媒体服务，不纳入这一阶段。
- 达到上述收口条件后，搜索、每日推荐、热榜、播放/队列、收藏、历史、歌词、歌单、分享、睡眠定时、管理后台与短评 MVP 可作为 **V1 可运行范围**；不宣称与网易云全功能等同。
- 每项通过明确验收后即停止；只有出现真实反馈、测试失败记录或使用数据，才开启下一轮。

## 权益与安全边界

- 版权曲库、MV、离线缓存和高解析音源需要授权与实际媒体服务，本项目不抓取第三方平台数据或素材。
- 现有音频为本项目生成的演示音频；生产环境应仅使用已获授权的文件，并配置版权、删除与投诉流程。
- 个性化历史与收藏均按用户隔离；提供删除/清空入口，不能通过猜测 ID 读取私密歌单。
